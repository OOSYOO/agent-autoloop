# GitLab Review 验证记录

本记录只描述当前方案；使用原生 Codex 配置，不再以额外沙箱或工具禁用作为验收要求。审查、扫描、通知和发布复用现有中台，不引入另一套调度。

## 自动化验证

系统 Node v26.4.0 下，提交前 `npm run test:quick` 371 项通过，`npm run typecheck`、`npm run format:check` 和 `git diff --check` 通过。

测试使用临时目录、随机端口、假 Codex/glab/飞书服务，覆盖：

- main 专用工作树创建与复用，日常开发目录不受影响。
- 唯一可信 prompt、原生 Skill 依据变化、运行中配置变化及缓存失效。
- 扫描、请求去重、完整 MR 文字资料、Hub/Worker 回执与人工回答续办。
- 发布前版本及依据复核、重复批准、未知写入响应核查和重复评论防护。
- 卡片展示 findings、可点击链接、零 findings 通知和模型执行失败。
- 本地安装、源码目录改名、更新和卸载保留私有数据。

现有预算按已确认要求为：空闲 RSS 不超过 150 MB，逐条持久化写入至少 100 条/秒；模拟吞吐只作观察。本次未改变内核或持久化实现。

## 实际部署与验证边界

2026-11-04 已在本人授权的实例完成静态审查、飞书确认及 GitLab 评论发布。后来更新为单一 main 工作树和原生 Codex 配置；该更新的自动化验证没有发送真实消息或创建真实 MR。安装恢复后，既有五分钟定时扫描继续运行。

原生目录能发现 `code-review` 和 `neat-freak`；该机器的 `ponytail` 未出现在目录结果中，不能据此声称已加载。Skill 目录可见不等于模型实际执行，具体一轮须查私有报告的 prompt、main/MR SHA、依据摘要和模型事件日志。

私有报告、配置、部署备份及账号信息保留在实例数据目录，不作为仓库提交内容。旧配置不兼容；历史日志和报告保留，不做数据迁移。

## 提交前审查与精简

- 删除未使用的补充资料处理、过时的强制写入拒绝冒烟、重复 Markdown 报告及环境转发包装。
- 新结果与缓存结果共用发卡前策略/MR 复核及 JSON 落盘；运行中版本或准入变化不发过期卡。
- POST 前条件失效或读取失败时释放确定未发送的意图；POST 结果未知仍不重发。
- 无人工覆盖、已投递的同版本手动观察可被自动扫描复用，避免重复卡；人工覆盖不被自动请求继承。
- 原生 Skill 附属文件采用流式摘要，不因任意总大小门槛或坏链接阻断全部审查；内容和可读取状态仍参与失效判断。

新增故障均先用假服务复现再修复，关键 Hub/Worker 集成回归通过。没有为验证创建真实 MR 或发送真实消息。
